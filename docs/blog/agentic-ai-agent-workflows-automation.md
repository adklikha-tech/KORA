    <h2>Agentic AI provides the intelligence</h2>
    <p>Agentic AI works toward a goal instead of responding to only one isolated prompt. It can understand context, consult approved knowledge, select an available tool, examine the result, and determine what should happen next.</p>
    <p>This makes an agent useful when the path cannot be completely predicted in advance. It may need to request missing information, choose between several options, consult a specialist, or adjust its approach when a result is incomplete.</p>

    <h2>Agent workflows provide the operating structure</h2>
    <p>An agent workflow defines how that intelligence is applied. It brings together the agent's role, instructions, knowledge sources, available tools, decision boundaries, approval requirements, and completion conditions.</p>
    <p>The workflow can change direction according to context without becoming uncontrolled. It gives the agent room to decide while keeping its work aligned with the rules established by the organization.</p>

    <div class="blog-callout">
      <strong>One practical model</strong>
      <p>The agent understands and decides. The agent workflow coordinates and governs. Automation performs the work.</p>
    </div>

    <h2>Automation turns decisions into action</h2>
    <p>Reasoning alone does not complete a business process. Once an agent has determined the appropriate next action, an approved automation flow can carry it out across the relevant application, document, data source, or connected service.</p>
    <p>The agent can provide inputs to the automation, wait for the result, evaluate what happened, and decide whether to continue, retry, request approval, or escalate an exception.</p>

    <h2>How the three layers work together</h2>
    <p>Consider a purchase request that needs to be reviewed before it can be processed. An agent can interpret the request, check the available information, consult approved business knowledge, and identify missing or unusual details. The agent workflow can require a person to approve the request. After approval, an automation flow can complete the repeatable system actions and return the result to the agent.</p>
    <p>This combination provides flexibility where judgment is needed and consistency where execution must be dependable.</p>

    <h2>Designed for governed outcomes</h2>
    <p>Likha is designed around governed autonomy rather than unrestricted action. Teams determine what agents can know, which tools they can use, when human approval is required, and what execution information should be retained for review.</p>
    <p>The result is an intelligent operating model: give AI a goal, provide a governed path, and connect it to the tools required to complete meaningful work.</p>
